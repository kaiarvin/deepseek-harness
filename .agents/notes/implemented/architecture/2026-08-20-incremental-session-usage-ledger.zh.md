# Agent Note: 增量会话用量账本

Status: implemented

[English](2026-08-20-incremental-session-usage-ledger.md) | 中文

> 细化了 [跨会话 token 用量报告与 Web 用量对话框](../feature/2026-08-15-cross-session-usage-report.zh.md) 中引入的聚合机制：报告形状、apiproxy 的 `usage.report` 线上接口与客户端对话框均未改动，只有宿主侧聚合发生变化。

## 问题

Web 用量对话框会卡住数十秒。`@deepseek-ai/dsh-session-usage-report` 原来按需折叠整个会话语料：`report()` 提供带 stale-while-revalidate 窗口的缓存，但一旦缓存变脏并超过 30 秒窗口，下一次打开就会同步重新扫描。折叠通过 `ctx.sessionQuery` 精确读取每个会话的完整日志；随着语料增长（单个工作会话就达到约 57 万事件 / 29 MB），一次扫描跨过 30–45 秒，因此在有会话持续写入的情况下，对话框每次打开都要"加载"这么久。设计假设扫描很便宜，这个假设不再成立。

## 决策

在同一服务内，把按需扫描折叠替换为增量、持久化的用量账本：

- 每条携带 provider `usage` 的 `assistant/message` 在追加到活动会话的那一刻就落成一条样本（时间、provider、model、sessionId、计费 token）；`request/header` 事件更新每个会话的归属。`report()` 按请求的本地日对内存样本分桶并瞬时返回——没有语料读取，没有陈旧窗口。
- 样本持久化到单个文件（`usage-report-samples.json`，原子临时文件替换、防抖写入、fiber 销毁时冲刷）。重启后加载该文件；首次启动后不再扫描语料。
- 首次启动且没有样本文件时回填一次：通过 `ctx.sessionQuery` 精确读取把完整语料折叠成样本（与之前相同的逐会话失败跳过容忍度）。回填与实时火线按序号对账——`session/event` 只在实时追加时触发（构造种子从不发布，因此重放/fork/恢复不可能重复计数）；实时事件若其 `seq` 落在该会话回填读取边界内，则已被那次读取计入，直接丢弃。
- 早于 `retentionDays`（默认 40）的样本在加载与写入时裁剪；对话框最多展示 30 天，账本保持有界。
- 查询接缝保持可选（`ctx.get('sessionQuery')`，活动 fiber 读取）：没有它时服务只走火线，跳过回填。

旧的 `freshMs`/`diskFreshMs` 配置与按时区的持久化文件已移除。报告形状、apiproxy 的 `usage.report` 线上接口与客户端对话框均未改动。

## 备选方案

**加速扫描（增量折叠检查点、更便宜的读取）。** 否决：对按需扫描设计而言，语料读取成本不可削减——任何一次打开仍可能付出完整折叠，而折叠本身已经是带并发上限的单遍扫描。这是架构问题，不是常数因子。

**更长的 stale-while-revalidate 窗口。** 否决：它只是推迟卡顿；脏且陈旧的缓存上的同步重扫仍然阻塞打开，而忙碌的会话会让缓存无限期保持脏。

**通过 `session.list` + `session.history` 在客户端聚合。** 在原始笔记（[跨会话 token 用量报告](../feature/2026-08-15-cross-session-usage-report.zh.md)）中已否决，现在依然如此：每次打开都要通过分页线上接口重新拉取历史，聚合应该属于日志而不是浏览器。

选定设计把成本移到写入端（每条带用量的消息一条样本），让打开时间变成 O(内存中样本数)——实际可视为零。事件流是正确的数据源：仓库已经信任 `session/event` 作为权威追加通道（token-meter 的投影就骑在同一条火线上），而构造种子从不发布，正是增量计数器所需的"不重复计数"保证。

## 结果

- 首次启动后对话框瞬时打开；报告调用不再读取语料。
- 本次改动后的首次启动会付出一次完整语料回填（旧设计每次打开都要付出的同样的 30–45 秒成本），然后写入样本文件。
- 账本按用量发生时间计数：压缩或删除会话不会追溯移除其已计入的用量（按需扫描折叠本来也会丢失压缩掉的历史；账本至少保留了它）。
- 配置面变化：`freshMs`/`diskFreshMs` 移除；新增 `retentionDays`（默认 40）与 `persistDelayMs`（默认 1000）。旧的按时区持久化文件被忽略（文件名与格式不同）；回填会重新生成一切。
- `usage.report` 线上契约、对话框的 7/30 天范围与按时区的日分桶均未改变。

## 测试

测试套件围绕新契约重写：真实 `session.append` 驱动的实时路径聚合（即时、零语料读取）、回填路径播种（一次冷遍历、与并发实时追加的序号对账）、无语料读取的持久化往返、损坏/版本不匹配/非对象/畸形样本文件、保留期裁剪、销毁冲刷、失败目录、失败读取/枚举，以及无查询接缝模式。src 逐文件覆盖保持 100%。
