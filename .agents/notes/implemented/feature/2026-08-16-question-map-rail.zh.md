# Agent Note：QuestionMap —— 长对话左侧的速览地图条

Status: implemented

[English](2026-08-16-question-map-rail.md) | 中文

## 问题

对话过长时想回看某个提问很费劲：读者必须滚动整段记录并肉眼寻找问题。界面上既没有「问题在对话流中处于什么位置」的概览，也没有跳转到某条提问的捷径。

## 决策

一条纯客户端的速览地图条，位于对话记录滚动区左缘（`ui-conversation` 的 `ChatView`）：

- **数据**：`ChatView` 按流顺序为每个 `user` 或 `steering` Chat 节点投影一条 `QuestionMapEntry`——assistant、tool、context 与生命周期节点不算提问。悬停提示文本取消息的文本块拼接，折叠空白、去首尾、截断到 180 字符；纯图片提问回退到本地化的 `[图片消息] / [Image message]` 标签。
- **几何**：速览条用 `position: fixed`，每次测量时以滚动区 rect 重新锚定（left + 8；阅读区 top + 16，高度 = clientHeight − `--dsh-composer-height` − 16）。选 fixed 而非 sticky，理由与 Tooltip 原语选 fixed 相同：对话列激活阶段在根元素上设置了 `overflow: hidden`，且 composer-overlay 视图模式会裁剪视图区（`[data-conversation-composer-overlay]`），sticky 会因此丢失滚动区。代码库已保证祖先无 transform，fixed 不会被困在某个包含块里。
- **横杠**：横杠紧挨成一簇——每根是位于簇顶 `索引 × 9px` 处的 7px 命中区（可见标记 11×3），彼此间隔 2px——整簇在阅读区内垂直居中，因此无论对话流多长，速览条都保持为一个紧凑的索引。阅读边缘（最后一个行顶 ≤ 滚动区顶 + 16 的提问）的横杠标蓝，其余为中性色。悬停是可感知的状态变化：标记伸满整条横杠宽度并变亮，命中区背后同时亮起交互悬停底色（减少动态效果偏好会关掉过渡）。悬停也以 `Tooltip`（右侧、150ms 延迟）显示提问文本；点击把对话滚动到该提问行顶距滚动区顶部 16px 处——跳转是视口相对增量（行顶 − 滚动区顶 − 16），任意滚动位置都能精确落位，`ChatView` 既有的滚动监听会重新推导跟随归属与已保存的读者位置，因此无需与它的记账逻辑耦合。速览条最多固定显示 10 根横杠（`RAIL_MAX_BARS`）：簇超出后它变为自己的滚动容器——隐藏滚动条、`pointer-events: auto` 使其可接收滚轮输入（到达边缘时滚轮会链式转交给对话记录）——并由一个布局 effect 保持当前提问可见，因此整段对话在长度有界的速览条内始终可浏览，「你在这里」的标记也保持可达。
- **可见性门**：仅当会话内至少有两个提问、且记录确实可滚动（`list.scrollHeight > scrollport.clientHeight + 8`）、且视口在编辑器上方留有空间时才渲染。一个滚动监听（驱动当前位标记；速览条自身几何在滚动中不变）加一个观察滚动区与流列表的 `ResizeObserver`（驱动窗口缩放、header 收起、流式增长与翻页后的重锚定）。速览条隐藏时不挂任何监听；两个 effect 会在条目变化使其复活时重新执行。
- **全程覆盖**：`ChatView` 会在后台持续翻页加载更早历史直到加载完（`hasMore && !loadingOlder → loadOlder()`，每页完成后快照翻转再次触发），因此速览条的条目始终覆盖完整对话——长会话刚打开时不再只显示尾部窗口内的提问，读者也无需手动往上翻。泵式加载一次一页（运行时自带并发保护），到 `hasMore === false` 或某页失败即停，并在重连/resync 重置窗口后自动重新覆盖。
- **成本纪律**：测量过程只读取提问行的 rect（从不读全部行）；`ChatView` 的渲染经济学与滚动归属逻辑原样未动——速览条是拥有自己 refs（`listRef`；滚动区在每次测量时经 `closest('[data-conversation-scroll]')` 解析，溢出跟随则用速览条自己的 `railRef`）的兄弟组件。

## 备选方案

**用 sticky 零尺寸座位而不是 fixed。** 否决：sticky 相对最近的滚动容器定位，而对话根元素激活阶段的 `overflow: hidden` 加上 composer-overlay 视图模式会在对话正需要滚动时把它弄坏（composer 座位能用只因它是 scrollBody 的直接子元素）。带逐次测量锚定的 fixed 定位正是本代码库 Tooltip 原语已在用的技术。

**用比例定位而不是紧凑簇。** 最初实现把每根横杠放到该提问在流中的比例位置（`(rowTop − listTop) / list.scrollHeight`）。评审后否决：用户要的是一个紧凑的索引——横杠紧挨在一起并垂直居中——而比例散布会让速览条高如整段记录，且每次增长都要重新排布。紧凑簇保持为一个小型控件，阅读边缘标记与点击跳转仍然承担位置与导航语义；簇超出固定 10 根的长度时在条内滚动，而不是越拉越长。

## 影响

长对话获得一眼可读的提问索引与一键导航；速览条只在有用时才出现（≥ 2 个提问、记录可滚动），短对话保持清爽，长对话则保持为固定大小的小控件——超过 10 根的簇在条内以滚轮滚动，而不会长到占满整屏。新增覆盖：`question-map.client.spec.tsx`（投影、紧凑簇定位、当前位标记、悬停、跳转、可见性门、固定上限与溢出跟随几何、监听生命周期）以及 chat-view 的泵式加载测试（后台翻页、不并发、加载完即停）。无需宿主改动；该功能是纯客户端对既有节点与滚动几何的组装。
